# Our Hangout · My Diary 통합

하단은 **사람 / 대화 / 지키미 / 일기**입니다. 가족·위치·프로필·앱 관리는 상단 설정으로 이동했습니다. 공통 색·타이포·헤더는 My Diary의 라벤더·핑크·밀키 화이트 방향으로 정리했습니다.

## 일기

My Diary 0.3.0의 자체 구현 소스 모듈을 `android/app/src/main/java/com/ourhangout/diary`와 `android/app/src/main/assets/diary`에 통합했습니다. 별도 앱 설치 없이 같은 APK 안에서 전체 화면 일기 편집기를 열고 ‘아지트’로 돌아옵니다. 하단 일기 탭은 쓰기와 기록 펼치기만 제공합니다.

서식·사진·영상·음성·파일·그림·태그·템플릿·달력·통계·휴지통·PIN/기기 잠금·알림·위젯·ZIP·TXT/PDF 기능을 유지했습니다. 녹음 시에만 마이크 권한을 요청합니다. 일기 전체 기능은 Android 구현입니다. iOS/Web에는 아직 네이티브 일기 편집기가 없습니다.

기기의 암호화 파일·첨부·PIN·초안·키는 서버 주소와 로그인 계정으로 분리합니다. 기존 독립 My Diary 앱의 저장소를 직접 읽지 않으며, My Diary의 백업 내보내기 → 통합 일기의 백업 가져오기를 이용합니다.

일기 상세에서 ‘지키미와 이 이야기 나누기’를 선택하면 선택한 글만 지키미 입력창에 담깁니다. 자동 전송·전체 일기 자동 읽기는 하지 않습니다. 지키미 대화 저장도 계정별로 분리합니다. 이전 계정 정보가 없는 공통 지키미 기록은 원본 키에 보존하며 새 계정에 자동 배정하지 않습니다.

## 서버 백업

서버의 migration 023과 `storage/diary` 볼륨이 필요합니다. 기록·첨부·초안·휴지통·템플릿을 My Diary 호환 ZIP으로 업로드합니다. 서버는 경로·중복·최대 용량·첨부 누락·SHA-256을 검사하고 계정별 불변 버전을 남깁니다. 동일 ZIP 재전송은 중복 생성하지 않습니다.

작성 후 잠시 입력이 멈추면 백업하며, 일기를 다시 열 때도 미전송 기록을 확인합니다. 오프라인이면 암호화된 기기 기록을 유지합니다. 앱을 즉시 닫았거나 Android가 프로세스를 종료했다면 다음에 일기를 열거나 ‘지금 서버에 보관’할 때 다시 시도합니다. 별도 백그라운드 작업 서비스는 추가하지 않았습니다.

서버 버전이 달라졌다면 자동 덮어쓰기를 중단합니다. 일기 설정에서 ‘서버 백업 가져오기’ 또는 명시적 확인 후 ‘이 기기의 기록으로 새 버전 만들기’를 선택합니다. 가져오기는 기존 기기 파일의 복구용 사본을 먼저 보존합니다. 잠금 설정은 이 기기의 설정을 유지합니다. 원격 PIN 비밀정보는 백업하지 않습니다.

액세스 토큰은 일기를 여는 동안 메모리에만 전달합니다. 토큰이 만료되면 암호화 기록을 유지하고 아지트로 돌아가 다시 일기를 열도록 안내합니다. 원래 앱과 독립된 refresh-token 회전은 하지 않습니다.

마스터는 전체 기록 조회·검색·휴지통 확인·첨부 ZIP 다운로드·ZIP 가져오기·이전 버전 복구·이전 복구 지점 삭제를 할 수 있습니다. 현재 버전은 삭제할 수 없으며 복구는 새 버전을 만듭니다. 사용자별 5GiB 보관 한도, ZIP 최대 약 1.1GiB, JSON 40MiB, 첨부당 128MiB를 적용합니다. 수동 ZIP 백업 파일은 평문이므로 비공개 장소에 보관합니다.

## 지키미 연결

xAI/Ollama/vLLM을 설정 목록에서 제거하고 OpenCode를 추가했습니다. OpenRouter·OpenCode·사용자 지정 API를 제공합니다. OpenCode는 https://opencode.ai/inference/openai/v1 와 공개 모델 목록을 사용하며 Chat Completions 형식의 모델만 표시합니다. Responses/Anthropic/Gemini/System One 모델은 프로토콜이 달라 제외합니다. API 키는 기기 SecureStore에 보관합니다. 실제 유료 모델 호출은 테스트하지 않았습니다.

다정한 존댓말·편한 반말·차분한 안내를 선택할 수 있으며, 대화 화면에서 기술 설정을 숨기고 설정에서 연결·세부 규칙을 펼쳐봅니다.

## 확인 범위

앱 타입 검사·Expo 설정 검사, 앱 회귀 테스트, Android API 36 기준 일기 네이티브 코드 컴파일, 서버 타입 검사·PostgreSQL 호환 PGlite 통합 테스트, 실제 웹/앱 구성 요소 화면 검토를 수행합니다. 운영 DB와 사용자 일기는 테스트하지 않습니다.

전체 APK 빌드는 기존 Firebase `google-services.json` 또는 README에 나온 환경변수 경로가 필요합니다. 이 체크아웃에는 Firebase 설정 파일이 없어 전체 APK 빌드·실기기 통합 검증은 별도 수행해야 합니다. 운영 배포와 실제 DB migration은 이 코드 작업에서 실행하지 않습니다.
