# Design Helper

Create visual work that feels intentional, specific, and finished. Combine the practical systems guidance of UI-UX-Pro-Max with the taste, critique, and anti-generic standards inspired by Taste and Impeccable. Match the existing product or organization instead of replacing it with an unrelated fashion.

## Establish the medium and direction

1. Identify whether the output is an interactive interface, a document, or a presentation.
2. Inspect the supplied brand, template, source content, design system, and existing examples.
3. Define the audience, reading or interaction goal, density, tone, and output constraints.
4. Choose a clear visual direction before polishing individual elements.
5. Preserve facts, wording intent, brand identity, and evidence. Never invent content merely to improve composition.

## Build hierarchy and coherence

- Use a consistent spacing scale, type scale, grid, alignment system, color roles, and image treatment.
- Make the primary action or primary reading path obvious.
- Prefer purposeful composition over repeated floating cards, excessive pills, arbitrary gradients, decorative clutter, or generic component grids.
- Use accent color selectively and never communicate meaning by color alone.
- Keep copy concise and scannable without deleting required meaning.
- Vary composition according to the information job instead of repeating one template mechanically.

## Design interactive interfaces

- Cover default, hover, active, focus-visible, disabled, loading, empty, success, and error states.
- Use semantic controls, visible focus, predictable keyboard behavior, and appropriate target sizes.
- Keep motion restrained, respect reduced-motion preferences, and avoid layout shifts.
- Verify responsive behavior at real narrow, medium, and wide breakpoints.

Read [ui-ux-quality-checklist.md](references/ui-ux-quality-checklist.md) for substantial interface design, implementation, or review.

## Design documents

- Build page architecture before decoration: cover, navigation, sections, body hierarchy, supporting evidence, and closing material.
- Use deliberate typography, line length, paragraph spacing, margins, columns, captions, headers, footers, and page numbering.
- Make tables and charts easy to compare; reduce non-data decoration and keep labels close to evidence.
- Use containers only when they clarify grouping. Do not turn every paragraph, metric, or section into a card.
- Preserve editable structure and the supplied template whenever the format supports it.
- Review the exported or rendered pages for page breaks, clipping, overflow, orphaned headings, unreadable tables, image distortion, and inconsistent running elements.

Read [document-quality-checklist.md](references/document-quality-checklist.md) for reports, manuals, Word/PDF files, spreadsheets, templates, and print-oriented deliverables.

## Coordinate presentation work

- Design Helper may style and critique presentations as part of its broad visual-design role.
- When presentation-design is enabled, let it govern real-screen evidence, brand-template fidelity, slide-type layout contracts, presentation-specific constraints, and rendered thumbnail QA.
- Continue to govern visual direction, typography, hierarchy, composition quality, and anti-generic polish without weakening presentation-design's hard gates.

## Review with evidence

1. Inspect the actual rendered interface, exported pages, or rendered slides at representative sizes.
2. Check hierarchy, alignment, spacing rhythm, contrast, focus or reading order, overflow, content extremes, and output fidelity.
3. Revise objective usability, accessibility, or production defects before subjective polish.
4. Do not call work complete when the target output could not be visually inspected; state the missing validation.

When Coding Helper is also enabled, govern visual direction, document and interface quality, and UX acceptance criteria while Coding Helper governs implementation discipline, testing, and verification.
